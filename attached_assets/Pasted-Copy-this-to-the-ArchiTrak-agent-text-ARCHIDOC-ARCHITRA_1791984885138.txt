```text
ARCHIDOC → ARCHITRAK SUPPLIER DIRECTORY CONTRACT v1

STATUS
Implemented and tested in ArchiDoc development. Not yet published.
Prepare the ArchiTrak changes now, but do not switch production traffic until
ArchiDoc confirms the endpoint is live.

PURPOSE
Replace the supplementary GET /api/suppliers request that caused sync failures.
That endpoint remains browser-session protected.

Keep contractor imports on GET /api/sync/contractors.
The new endpoint supplies supplier-directory data, not contractor data.

AUTHENTICATION
Production base URL: https://archiouvro.com

Use the existing:
Authorization: Bearer <accepted sync key>
Accept: application/json

Keep ArchiTrak’s current credential selection unchanged. Its _NEXT credential
was confirmed to return 200 against production /api/sync/trades.

ArchiDoc validates the supplied bearer value against its ARCHIDOC_SYNC_API_KEY.
No new credential is required.

FIRST REQUEST
GET /api/integrations/architrak/v1/supplier-directory?limit=200

Limit:
- Default: 200
- Minimum: 1
- Maximum: 500

SUBSEQUENT REQUESTS
GET /api/integrations/architrak/v1/supplier-directory?cursor=<nextCursor>

Treat cursors as opaque and URL-encode them.
Do not send limit alongside cursor.
No filters, since parameter or incremental mode are supported in v1.

RESPONSE SCHEMA

type SupplierDirectoryResponse = {
  schemaVersion: 1;
  scope: "supplier-directory";
  sources: ["supplier-library", "ff-suppliers"];
  snapshotId: string;
  snapshotAt: string;       // Database transaction timestamp, UTC ISO
  expiresAt: string;        // UTC ISO
  totalCount: number;       // Total across ALL pages
  items: SupplierDirectoryItem[];
  nextCursor: string | null;
  complete: boolean;       // True only on the final page
};

type SupplierDirectoryItem = {
  id: string;
  source: "supplier-library" | "ff-suppliers";
  sourceId: string;
  paymentSupplierId: string | null;
  name: string;
  legalName: string | null;
  siret: string | null;
  specialty: string | null;
  website: string | null;
  email: string | null;
  phone: string | null;
  contacts: Array<{
    id: string;
    name: string | null;
    email: string | null;
    phone: string | null;
    isPrimary: boolean;
  }>;
  status: "active" | "inactive" | "deleted";
  deletedAt: string | null;
  createdAt: string;
  updatedAt: string;
};

Optional scalar values are null, not invented.
Contacts may be an empty array.

This is an allowlisted directory feed, NOT a raw-table export. It does not
include banking details, protected-document links, private notes or AI analysis.
Do not clear existing local fields merely because they are outside this schema.

IDENTITY

Supplier-library IDs:
  supplier-library:<original-id>

Partners/F&F supplier IDs:
  ff-supplier:<original-id>

sourceId contains the original ID serialized as text.

The two sources are distinct namespaces. A supplier-library ID "7" is not the
same identity as an F&F supplier ID "7".

Do not automatically merge records by name or email.
Names can change without changing identity.

For previously imported supplier-library rows, migrate the existing external
identity to supplier-library:<original-id>, rather than creating duplicates.

paymentSupplierId is populated only when ArchiDoc already has an explicitly
allocated payment identity. Never synthesize it or infer payment eligibility
from presence in this directory.

CONTACTS

Supplier-library primary contact ID:
  supplier-library:<original-id>:primary

Separate F&F contact ID:
  ff-supplier-contact:<contact-id>

Fallback F&F primary contact ID:
  ff-supplier:<original-id>:primary

The F&F fallback is used only when no separate contact rows exist and primary
contact fields contain data.

Treat contacts as the current contact list for that supplier.
A contact change may not advance the parent supplier’s updatedAt timestamp:
do not skip importing contacts solely because updatedAt is unchanged.

ACTIVE / DELETED SEMANTICS

Supplier-library:
- Existing records report status="active".
- This source has no inactive flag.

F&F suppliers:
- deletedAt present → status="deleted"
- Otherwise isActive=true → status="active"
- Otherwise → status="inactive"

Both active and inactive records are included; retained soft-deleted records
are included too.

Some deletions are hard deletions. Historical tombstones for every deletion
are NOT guaranteed. Detect those absences only after a complete successful
snapshot.

CONSISTENCY GUARANTEE

ArchiDoc reads both supplier sources and contacts in one read-only
REPEATABLE READ database transaction.

All pages are served from a fixed export sorted by stable supplier ID.
Edits or deletions after the export is created cannot change subsequent pages.
Retrying the same cursor returns the same page while the snapshot remains valid.

Snapshots expire after 30 minutes.
They are process-local: publishing or restarting ArchiDoc invalidates them.

RECONCILIATION ALGORITHM

1. Request the first page and create a staging import.
2. Validate schemaVersion, scope and both expected sources.
3. Retain snapshotId and totalCount.
4. Follow nextCursor until null.
5. Require every page to use the same snapshotId and totalCount.
6. Reject duplicate supplier IDs or malformed responses.
7. Require:
   - final complete=true;
   - final nextCursor=null;
   - unique supplier count equals totalCount.
8. Only then commit the staged import and reconcile absent records.

A successful empty snapshot is valid.

Missing previously imported supplier IDs may be marked absent/archived only
within these supplier source namespaces. Preserve historical/payment links.

Never use this supplier snapshot to reconcile contractor records, locally
created records, or records belonging to another integration.

On any failure, retain the previous completed import. Do not interpret failure
as an empty supplier directory. Do not advance the successful supplier-sync
timestamp until the full snapshot is committed.

ERRORS

400 {"error":"INVALID_QUERY"}
Invalid limit, cursor format, unsupported parameter, or limit with cursor.
Fix the request; do not retry unchanged.

401
Missing or invalid bearer credential.
Stop and report authentication failure. Do not silently change keys.

503 {"error":"Sync API not configured"}
ArchiDoc has no configured sync credential. Operator action required.

410 {"error":"SNAPSHOT_EXPIRED","restartRequired":true}
Unknown/expired cursor, including after a server restart.
Discard staged pages and restart from page one.
Do not perform absence reconciliation.

503 {"error":"SNAPSHOT_UNAVAILABLE","retryable":true}
Source loading failed. No partial successful export is returned.

503 {"error":"SNAPSHOT_CAPACITY","retryable":true}
Export/cache capacity reached.
Preserve the previous import and retry later with bounded backoff.

Network failures, non-JSON responses and unsupported schema versions must also
fail the import without reconciliation. Do not treat HTTP 200 HTML as success.

ROLLOUT

1. Implement the new reader and staging/reconciliation logic.
2. Add tests for multiple pages, repeated cursors, expiration, partial failure,
   empty complete exports, duplicate IDs and existing-ID migration.
3. Wait for confirmation that ArchiDoc has published this endpoint.
4. Make a read-only authenticated request and validate the response contract.
5. Restore supplier import using this endpoint instead of /api/suppliers.
6. Report contractor and supplier outcomes separately so a supplementary
   supplier failure does not misleadingly report successful contractor work
   as zero updates.

Do not weaken authentication, rotate credentials or delete historical records.
```
